# Documentação, Mudanças e Release

- Toda tarefa concluída deve ter relatório de mudanças verificável.
- Relatório deve listar arquivos/módulos afetados, comportamento anterior/novo, dados/APIs/configs impactados, testes executados, riscos e pendências.
- ADR deve registrar decisões arquiteturais relevantes com contexto e trade-offs.
- Documentação deve refletir comportamento real; comandos precisam ser executáveis.
- Release Manager exige evidências dos gates proporcionais ao risco.
- Release crítica deve ter rollback/recuperação viável.
- Nunca chamar de “produção pronta” aquilo que não foi validado no ambiente/artefato apropriado.
- Exceções aceitas precisam ficar explícitas com risco residual.
